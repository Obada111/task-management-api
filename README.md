# Task Management API

A beginner-friendly REST API for managing tasks, built with Node.js, Express.js, and TypeScript. All data is stored in a local JSON file. No database is used.

## Features

- Create, list, view, update, and delete tasks.
- Change a task status independently.
- Filter tasks by status and priority.
- Search task titles and descriptions.
- Sort by createdAt, dueDate, priority, or title.
- Paginate results with page and limit.
- Get task statistics grouped by status and priority.
- Validate request data with express-validator.
- Centralized error handling with a consistent response format.
- Safe JSON file storage that creates missing files and serializes writes.

## Technology

- Node.js

- TypeScript
- fs/promises for JSON file storage

## Data Storage

Tasks are stored in `data/tasks.json`. The server loads this file once at startup. The file and directory are created automatically when they do not exist. After every change, the full task list is saved back to the file. Saves are queued so overlapping requests do not silently overwrite each other.

If the file contains invalid JSON, the server stops at startup with a clear error message and does not overwrite the file. Fix the file and start the server again.

Because tasks are loaded at startup, restart the server after editing `data/tasks.json` manually.

## Response Format

Success response:

```json
{
  "success": true,
  "data": {
    "id": "task-id",
    "title": "Learn Express.js"
  }
}
```

List response includes pagination metadata:

```json
{
  "success": true,
  "data": [],
  "pagination": {
    "page": 1,
    "limit": 10,
    "total": 0,
    "totalPages": 0
  }
}
```

Error response:

```json
{
  "success": false,
  "message": "Task not found"
}
```

## Endpoints

| Method | Endpoint | Purpose | Success |
| --- | --- | --- | --- |
| GET | `/api/tasks` | List tasks with filters, search, sorting, and pagination | 200 OK |
| GET | `/api/tasks/stats` | Get task statistics | 200 OK |
| GET | `/api/tasks/:id` | Get one task | 200 OK |
| POST | `/api/tasks` | Create a task | 201 Created |
| PUT | `/api/tasks/:id` | Update task details | 200 OK |
| PATCH | `/api/tasks/:id/status` | Update only the task status | 200 OK |
| DELETE | `/api/tasks/:id` | Delete a task | 204 No Content |

### Query Parameters for `GET /api/tasks`

| Parameter | Values | Default |
| --- | --- | --- |
| status | pending, in-progress, completed | none |
| priority | low, medium, high | none |
| search | any text | none |
| sortBy | createdAt, dueDate, priority, title | createdAt |
| order | asc, desc | desc |
| page | positive integer | 1 |
| limit | integer from 1 to 100 | 10 |

Example:

```
/api/tasks?status=pending&priority=high&search=meeting&page=1&limit=10&sortBy=createdAt&order=desc
```

## Task Fields

| Field | Type | Required | Rules |
| --- | --- | --- | --- |
| id | string | generated | Unique identifier generated by the server |
| title | string | yes | 1 to 120 characters after trimming |
| description | string | no | Maximum 1000 characters |
| status | string | no | pending, in-progress, or completed. Default: pending |
| priority | string | no | low, medium, or high. Default: medium |
| dueDate | string | no | YYYY-MM-DD or null |
| createdAt | string | generated | ISO date-time set on creation |
| updatedAt | string | generated | ISO date-time set on creation and every update |

## Example Requests

Create a task:

```bash
curl -X POST http://localhost:3000/api/tasks -H "Content-Type: application/json" -d "{\"title\":\"Learn Express.js\",\"description\":\"Build my first REST API\",\"priority\":\"high\",\"dueDate\":\"2026-11-15\"}"
```

List tasks:

```bash
curl http://localhost:3000/api/tasks
```

Filter and search:

```bash
curl "http://localhost:3000/api/tasks?status=pending&priority=high&search=express"
```

Get one task:

```bash
curl http://localhost:3000/api/tasks/task-id
```

Update a task:

```bash
curl -X PUT http://localhost:3000/api/tasks/task-id -H "Content-Type: application/json" -d "{\"title\":\"Updated title\",\"priority\":\"medium\"}"
```

Update status:

```bash
curl -X PATCH http://localhost:3000/api/tasks/task-id/status -H "Content-Type: application/json" -d "{\"status\":\"completed\"}"
```

Delete a task:

```bash
curl -X DELETE http://localhost:3000/api/tasks/task-id
```

Get statistics:

```bash
curl http://localhost:3000/api/tasks/stats
```

## Validation Rules

- title is required when creating a task and cannot be empty after trimming.
- title must be at most 120 characters.
- description must be at most 1000 characters.
- status must be one of: pending, in-progress, completed.
- priority must be one of: low, medium, high.
- dueDate must be a valid date in YYYY-MM-DD format or null.
- Update requests must contain at least one valid field.
- Clients cannot overwrite id, createdAt, or updatedAt.
- Invalid page or limit values return 400.
- Malformed JSON request bodies return 400.

## HTTP Status Codes

| Status | When |
| --- | --- |
| 200 OK | Successful read or update |
| 201 Created | Task created |
| 204 No Content | Task deleted |
| 400 Bad Request | Invalid request data or query parameters |
| 404 Not Found | Task or route does not exist |
| 500 Internal Server Error | Unexpected server or file storage error |

## How to Test

### Start the server

```bash
npm run dev
```

The API is available at `http://localhost:3000`.

### Test with Postman

1. Open Postman and create a collection named "Task Management API".
2. Add a request for each endpoint in the Endpoints table.
3. For POST and PUT requests, choose Body > raw > JSON and paste a JSON body.
4. Send each request and check the status code and response.
5. Copy the id from a create response and use it in the get, update, and delete URLs.

Create request example:

- Method: POST
- URL: `http://localhost:3000/api/tasks`
- Body:

```json
{
  "title": "Learn Express.js",
  "description": "Build my first REST API",
  "priority": "high",
  "dueDate": "2026-11-15"
}
```

### Test with curl

List tasks:

## Testing Checklist

1. Create a task with valid data.
2. Try to create a task without a title and confirm a 400 response.
3. List tasks when the file has records and when it is empty.
4. Get an existing task and a non-existing task.
5. Update a task and verify id and createdAt do not change.
6. Update status with valid and invalid values.
7. Delete an existing and a non-existing task.
8. Test each filter alone and combined.
9. Search with different letter casing.
10. Test pagination boundaries and invalid page or limit values.
11. Break `data/tasks.json`, start the server, and confirm it stops with a clear error without overwriting the file. Restore the file to continue.
12. Send several create requests close together and confirm none are lost.
13. Create a task, restart the server, and confirm the task is still returned.

You can run these tests with Postman or curl. For Postman, create a collection with one request per endpoint and use the examples above as the request bodies.

## Notes

Local JSON storage is intended for learning and low-volume use. It does not provide transactions, indexing, or multi-process coordination. Do not run multiple server processes that write to the same JSON file. In a later project, the storage layer can be replaced with a database without changing the API contract.
